# Что нужно для запуска: HH, резюме, отбор

Проверено 8 сентября 2026. Это рекомендации по приоритетам, а не журнал
реализованных изменений. Состояние кода зафиксировано в
[аудите](2026-09-08-upstream-readiness-audit.md).

## Рынок и механика HH

Последний опубликованный месячный отчёт — август 2026, ссылка появилась
в [обзорах HH 7 сентября](https://hh.ru/article/26641).

| Показатель | Россия, весь рынок | Информационные технологии |
|---|---:|---:|
| Изменение среднего числа активных вакансий год к году | −13% | −33% |
| Изменение среднего числа активных резюме год к году | +22% | +19% |
| hh.индекс | 8,7 | 26,4 |

Источник: [отчёт за август, страницы 2 и 6](https://hhcdn.ru/file/18460655.pdf).
Индекс — отношение активных резюме к вакансиям, не число откликов на одно
объявление. ИТ — широкая категория, не отдельная оценка рынка BI-аналитиков.

В отборе нужно различать несколько механизмов:

- Умный поиск сопоставляет смысл опыта, навыки и параметры резюме;
  точное совпадение всех слов не обязательно.
  [Описание HH](https://feedback.hh.ru/knowledge-base/article/1116).
- Авторазбор может учитывать образование, языки, географию, опыт,
  доход и ответы чат-боту; доступны фильтры поиска кроме текстовых полей.
  [Документация от 27 июля](https://feedback.hh.ru/knowledge-base/article/9110).
- Новый ИИ-помощник извлекает критерии вакансии и сортирует кандидатов.
  Работодатель может менять критерии, соискатель их не видит. Сортировщик
  сам не отправляет отказ; отдельный навык уточняет информацию в чате.
  Функциональность ещё доступна не всем работодателям.
  [Документация от 28 августа](https://feedback.hh.ru/knowledge-base/article/022833).
- У работодателя может быть собственная ATS/CRM: её внутренние правила нам
  не доступны. Поэтому локальная оценка текста не является вероятностью найма.

HH указывает максимум 200 откликов за день. Также работодатель видит последнюю
версию резюме после его редактирования, в том числе по уже отправленному отклику.
[Официальная инструкция](https://feedback.hh.ru/knowledge-base/article/1618).
Отсюда рекомендация: устойчивые версии под роли, а не перезапись одного
HH-резюме перед каждой отправкой. HH поддерживает дублирование резюме.
[Инструкция](https://feedback.hh.ru/knowledge-base/article/1586).

## Приоритеты реализации

| Приоритет | Что довести | Проверяемый результат |
|---|---|---|
| P0 | Вход HH, контакты, файл CV, доступная AI-модель | Читается правильный аккаунт и опубликованное резюме; генерация возвращает содержательный ответ |
| P0 | Проверка готовности перед запуском | Видны конкретные причины блокировки: сессия, резюме, AI, права на отправку, квоты |
| P0 | Контрольный живой отклик | Правильные вакансия и resume_id, подтверждение доставки в истории HH, отсутствие дубля после перезапуска |
| P1 | Единая база фактов кандидата | Даты, роли, проекты, личный вклад, стек и подтверждённые результаты используются всеми AI-функциями одинаково |
| P1 | Две-три версии под реальные целевые роли | Выбор HH resume_id согласован с локальным PDF/DOCX и текстом; сохранена версия на момент отправки |
| P1 | Экспорт и обратное чтение CV | После экспорта извлекаются контакты, даты, проекты и навыки в правильном порядке |
| P1 | Объяснимый отбор | Для требования есть подтверждение из опыта, пробел либо явное несоответствие; важное неизвестное уходит на просмотр |
| P1 | Очередь вопросов работодателей | Известные факты доступны для ответа, неизвестные вопросы видны пользователю, уведомления не теряются |
| P1 | Учёт результатов по версии CV | Доставка, доступный статус просмотра, диалог, интервью, отказ; сравнение похожих вакансий и одинаковых периодов наблюдения |
| P2 | Управление расходами модели | Стоимость и ошибки запросов видны; повторная обработка неизменённой вакансии/резюме не нужна |
| P2 | Подготовка к интервью | TL;DR вакансии, темы, короткие ответы, задачи, пробелы и рассказ о реальном проекте |

Планировщик, квоты, восстановление и защита от повторных отправок уже есть.
Их нужно подтвердить в живом HH-сценарии, а не переписывать с нуля. Перед
постоянной работой проверить перезапуск процесса, истечение сессии и паузы
из-за сна/выключения компьютера.

База фактов может быть обычными структурированными данными в существующем
профиле/SQLite. Векторная база, новый оркестратор и дополнительные агенты
для этого не требуются. Каждая версия CV меняет акценты, сохраняя факты.

Для текущего профиля BI исходные варианты — BI-аналитик и аналитик данных;
третью роль выбирать только при подходящем опыте. Не смешивать BI, бизнес-
и системную аналитику в одну безразличную категорию. Сначала вручную разметить
30–50 вакансий «подходит / рассмотреть / мимо», затем проверить на них фильтры.
Это предложенный калибровочный набор, не исследование репрезентативной выборки рынка.

## Что убрать из первого запуска

- Одновременный запуск автоотклика на множестве непроверенных площадок.
  Сначала законченный HH-сценарий; остальные адаптеры оставить вне рабочей очереди.
- Автоматическое занесение компании в чёрный список только за быстрый отказ.
  В коде есть `ats_detected` по времени ответа; скорость не устанавливает причину отказа.
- Представление локального ATS-score как вероятности прохождения отбора.
  Полезнее показать пропущенное требование и соответствующий фрагмент опыта.
- Перезапись одного HH-резюме под каждую вакансию.
- Обязательное достижение дневного объёма за счёт неподходящих вакансий.
  Если подходящих меньше, отчёт должен показывать нехватку и причины фильтрации.
- Автоответы выдуманными фактами или шаблонным согласием при сбое модели.
- Расширение API-lab/HAR, сложного календарного sync и оформления интерфейса
  до завершения рабочего пути кандидата.

## Последовательность запуска

1. Устранить три обнаруженных блокера: HH auth, контакты/CV, отказ AI-провайдера.
2. Собрать факты и две версии резюме, проверить отображение на HH и экспорт.
3. Откалибровать отбор на небольшой размеченной подборке текущих вакансий.
4. Сделать один подтверждённый живой отклик и небольшую серию, проверить историю.
5. Настроить квоту 100–200/day и расписание при достаточном количестве подходящих
   вакансий. Обрабатывать входящие вопросы и измерять приглашения по версиям CV.

Google Calendar пока можно использовать через подключённого ассистента:
дата, время, часовой пояс, компания и ссылка на вакансию/созвон.
Отдельная интеграция Google в Work Hunter не блокирует поиск работы.
