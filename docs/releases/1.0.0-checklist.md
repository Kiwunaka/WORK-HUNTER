## Read-only auth-status fix

The final Docker audit found that the missing-token status command used to
create an empty SQLite database. The root cause was eager `Storage`
construction before CLI dispatch.

- A regression test first failed for both `hh-auth-status` and
  `hh auth status` because `.work-hunter` appeared.
- `Storage` is now initialized on first real use; `init` still explicitly
  creates the database and applies migrations.
- Focused tests: `3 passed`; complete onboarding file: `9 passed`.
- Independent subprocess review confirmed exit `0`, correct JSON, and no root
  directory for both command forms.
- Independent review verdict: ready; `0` Critical and `0` Important findings.
