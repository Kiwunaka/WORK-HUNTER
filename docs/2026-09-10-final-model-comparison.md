# Итоговое сравнение Muse, GLM и DeepSeek V4.1

10 сентября 2026. Сравнение завершено: три модели ответили на одинаковые семь
синтетических заданий. Последним выполнен DeepSeek V4.1 Flash high, после
включения нового маршрута OpenRouter. Все его ответы подтверждают модель
`deepseek/deepseek-v4.1-flash` и провайдера `DeepSeek`.

DeepSeek V4.1 показал заметно более пригодные для приложения результаты,
чем ранее проверенный V4 Flash: оба отбора, цитаты и переписка прошли,
факты проекта сохранены. В этом прогоне он быстрее Muse и GLM.
Это не доказательство устойчивого превосходства: на каждый сценарий получен
один ответ, запросы выполнены в разное время, задержки провайдеров меняются.

Для массового отбора и переписки Muse high остаётся экономичным выбором.
V4.1 high теперь обоснованный кандидат для подготовки к собеседованию и задач,
где важна скорость. GLM преимуществ для назначения основной моделью не показал.
После сравнения по запросу пользователя оставлена Muse Contributor high,
а DeepSeek V4.1 Flash high назначен резервом для текстовых задач через прямого
провайдера `deepseek`. При HTTP 404/410/503 или удалённом model ID (400 с
`not a valid model`) выполняется одна попытка на резерве. Ошибки ключа, баланса
и запреты доступа не переключают модель. Изображения на текстовый резерв
не отправляются. Фактическая модель и её usage записываются в статистику.

Для Muse задан `provider.max_price`: $0.10 за миллион входных токенов и $0.20
за миллион выходных — текущий тариф Contributor. При повышении цены OpenRouter
исключит подорожавший маршрут; ошибка отсутствия подходящих endpoints запустит
резерв. Ограничение Muse не переносится на DeepSeek. Настройки хранятся в
`ai.model_fallbacks`, `ai.model_max_prices` и существующем `ai.model_providers`.
[Документация лимита цены OpenRouter](https://openrouter.ai/docs/guides/routing/provider-selection).

## Стоимость и исходный бюджет

По фактическому usage V4.1 high стоит ×8.16 от Muse high этого прогона.
Относительно исходной базы Muse low ($0.001783188 за семь заданий с уточнённым
интервью) это ×14.12 — выше пользовательского лимита ×10 от low.

OpenRouter для прямого провайдера DeepSeek показывает пиковый тариф
$0.30 / $1.20 за миллион входных/выходных токенов и внепиковый $0.15 / $0.60.
При том же числе токенов вне пика набор стоил бы около $0.0125902 — ×7.06
от исходного low. Это расчёт по тарифу, не дополнительный измеренный прогон.
Кеш уже учтён в сохранённом usage; фактическая цена будущих запросов зависит
от их содержания, reasoning, кеша и действующих тарифов.

[DeepSeek: тарифы и расписание](https://api-docs.deepseek.com/quick_start/pricing/),
[OpenRouter V4.1](https://openrouter.ai/deepseek/deepseek-v4.1-flash).
Снимок тарифов провайдера: `outputs/deepseek-v41-metadata-2026-09-10.json`.

## Проверки на данных

Все три отдельных SQL-решения исполнены без изменения текста в SQLite на
прежних данных: несколько позиций и заказов, неоплаченные заказы, клиент без
заказов, оплаченный заказ без позиций. У всех получен ожидаемый результат:
`[(1, 2, 80), (2, 0, 0), (3, 0, 0), (4, 1, 0)]`.
Это проверка семантики запросов, не интеграционный тест PostgreSQL.

Ошибка Muse в интервью проверена контрпримером: два клиента, у одного два
заказа. COUNT(*) после LEFT JOIN равен трём, а не двум. Модель неверно назвала
его числом строк левой таблицы.

Ошибка GLM: для продаж A=10, A=20, B=30 его запрос возвращает доли 1/6, 1/3
и 1/2 на отдельных строках, а не доли менеджеров A=1/2, B=1/2. Для заявленного
вопроса нужна агрегация продаж менеджера.

Во всех трёх шпаргалках недостаточно раскрыта рамка оконной суммы при одинаковых
значениях ORDER BY. На данных month=1/amount=10, month=1/amount=20,
month=2/amount=5 рамка по умолчанию возвращает накопления 30, 30, 35.
Фраза DeepSeek «до текущей строки» без пояснения peers может ввести в заблуждение.
Его пример LEFT JOIN также выводит только id левой таблицы: упомянутые в тексте
NULL правой стороны в проекции не видны. Эти недостатки не равны ошибкам
COUNT(*) и группировки у других двух моделей, но шпаргалка не безупречна.

## Доступность и метод

Первоначальные проверки нового ID получали HTTP 400 при уже существующей
карточке без провайдеров. После просьбы проверить снова маршрут заработал:
проверка соединения HTTP 200, затем семь рабочих ответов HTTP 200/stop.

Проверка старого `~deepseek/deepseek-v4-flash-latest` возвращала имя 0731
от OpenInference. Её незавершённый рабочий запрос остановлен; результаты этого
алиаса не включены в сравнение новой модели. Публичное имя ответа само по себе
не доказывает или опровергает внутренний reroute у стороннего провайдера.
Для завершённого прогона использован точный новый ID.

Те же семь синтетических заданий и текущие парсеры приложения. Последовательные
запросы внутри каждого прогона; Muse и GLM работали параллельно, V4.1 — позже.
Лимит 16 000 выходных токенов вместе с reasoning, timeout 150 с. Все 21 рабочий
ответ завершились stop. Проверен один выбранный режим каждой модели,
не все доступные режимы reasoning.
